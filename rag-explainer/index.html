CHAPTER 00 · 一句话读懂 RAG

让大模型从「闭卷考试」变成「开卷考试」

01

为什么需要 RAG？——直击 LLM 的四大痛点

裸用大模型就像让一个博学的「外星人」替你做生意

🤥

幻觉 Hallucination

模型一本正经地胡说八道，编造不存在的案例、法规、产品参数。

RAG 解法：强制基于检索到的原文回答，每段标注出处
⏰

知识截止 Knowledge Cutoff

模型只知道训练截止日前的事，无法回答"上周发布的政策"、"今天股价"。

RAG 解法：知识库实时更新，检索时拉最新文档
🔒

私域盲区 Private Domain Blind

你公司的产品手册、内部 SOP、客户档案，模型从没见过。

RAG 解法：把企业文档向量化入库，模型"读"得到
📏

无法溯源 No Provenance

金融、医疗、法律场景需要"依据"，模型说"我觉得"是不够的。

RAG 解法：每条结论都挂接原文段落，可点击验证
02

RAG 到底是什么？

一个公式 + 一个比喻，三分钟讲透

核心公式
Answer = LLM ( Prompt ⊕ Retrieve(Query, KB) )

答案 = 大模型(系统提示 + 用户问题 ⊕ 从知识库检索到的相关内容)

📚

一个比喻：律师庭审

  • 用户提问 = 当事人抛出的法律问题
  • 检索环节 = 律师翻开案卷、找判例、查法条
  • Prompt 组装 = 律师把案卷摘要整理成陈述稿
  • LLM 生成 = 律师当庭陈述、当场辩护
  • 引用标注 = 律师指明"依据 XX 法第 X 条"
没有 RAG 的 LLM = 没带案卷上庭的律师，靠记忆瞎辩

进阶 RAG · 当基础 RAG 不够用时

从 Naive RAG → Advanced RAG → Modular RAG 的进化路径

L1

Naive RAG

最朴素的「问 → 检索 → 答」，适合 MVP 验证

  • Query 直接 Embedding
  • 向量检索 Top5
  • 塞进 Prompt 直接问
L2

Advanced RAG

加入改写、HyDE、Rerank、混合检索，准确率提升 30-50%

  • Query 预处理（改写/扩展）
  • Hybrid 检索（向量+BM25）
  • Cross-Encoder Rerank
  • 元数据过滤
L3

Modular RAG

把 RAG 拆成可插拔模块，按场景灵活组装

  • 检索前/中/后模块化
  • 支持多源异构数据
  • 可插拔 Reranker/Reader
L4

Agentic RAG

Agent 自己决定要不要检索、检索几次、用什么工具

  • Self-RAG：模型自评检索必要性
  • CRAG：检索质量评估 + 改写
  • Multi-Agent：多个专家协作
🔮

HyDE（Hypothetical Document Embeddings）

让 LLM 先"假设性"地写一段答案，再把这段答案去检索。绕过 Query 和文档的语义鸿沟。

Query → LLM(假设答案) → Embedding → 检索
🪞

Self-RAG

模型自己加 4 类特殊 token：[Retrieve]、[IsRel]、[IsSup]、[IsUse]，决定要不要检索、检索结果是否相关、答案是否有依据。

Self-RAG = 检索决策 + 反思 + 引用
🛠️

Corrective RAG (CRAG)

检索后立刻评估文档质量（Correct/Incorrect/Ambiguous），必要时触发 Web 搜索兜底。

检索 → 评估 → 不行就换源
🕸️

GraphRAG

用知识图谱替代扁平文档，把实体和关系建图。微软开源项目，适合"全局性问题"（如"公司整体战略"）。

文档 → 实体抽取 → 关系建图 → 图检索
🔁

Multi-Query / Multi-Step

一个问题拆成多个子问题分别检索，再合并答案；或者多轮检索逐步逼近真相。

Q → [Q1, Q2, Q3] → 分别检索 → 合并
📦

Long-Context RAG

当上下文窗口足够大（200K+），直接把 TopK 文档全部塞进去，跳过 Rerank 也能拿到不错效果。

检索 Top20 → 不 Rerank → 全部塞 LLM

5 分钟搭一个 RAG · 最简可运行代码

基于 LangChain + Chroma + OpenAI · 复制即可跑

"""
RAG 最小可用示例 - 基于 LangChain
前置：pip install langchain langchain-openai langchain-chroma chromadb
"""
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_chroma import Chroma
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import TextLoader
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough

# ========== 1. 文档加载 ==========
loader = TextLoader("company_handbook.txt", encoding="utf-8")
docs = loader.load()

# ========== 2. 文档切分 ==========
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,    # 每块 500 字
    chunk_overlap=50,  # 块之间重叠 50 字
)
chunks = splitter.split_documents(docs)

# ========== 3. 向量化 + 入库 ==========
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(chunks, embeddings)

# ========== 4. 检索器 ==========
retriever = vectorstore.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 4}  # 取 Top4
)

# ========== 5. Prompt 模板 ==========
template = """你是一个专业的企业知识助手。请基于【参考资料】回答用户问题。
如果资料里没有答案，请诚实地说"我不确定"，不要编造。

【参考资料】
{context}

【用户问题】
{question}

【回答】"""
prompt = ChatPromptTemplate.from_template(template)

# ========== 6. 组装 RAG 链 ==========
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

rag_chain = (
    {"context": retriever, "question": RunnablePassthrough()}
    | prompt
    | llm
)

# ========== 7. 提问 ==========
answer = rag_chain.invoke("公司年假是怎么规定的？")
print(answer.content)

"""
极简版 RAG · 不依赖任何框架 · 50 行讲透原理
"""
import numpy as np
from openai import OpenAI

client = OpenAI()

# ========== 1. 准备"知识库" ==========
docs = [
    "公司年假：工作满 1 年 5 天，满 3 年 10 天，满 5 年 15 天",
    "报销标准：经济舱机票可全额报销，酒店限 500 元/晚",
    "远程办公：每周三、五可申请，需提前 1 天报备",
]

# ========== 2. 把文档 Embedding ==========
doc_embeds = []
for d in docs:
    emb = client.embeddings.create(model="text-embedding-3-small", input=d)
    doc_embeds.append(emb.data[0].embedding)

# ========== 3. 用户提问 → Embedding → 算相似度 ==========
def retrieve(query, top_k=2):
    q_emb = client.embeddings.create(
        model="text-embedding-3-small", input=query
    ).data[0].embedding

    # 余弦相似度
    scores = [
        np.dot(q_emb, de) / (np.linalg.norm(q_emb) * np.linalg.norm(de))
        for de in doc_embeds
    ]
    top_idx = np.argsort(scores)[::-1][:top_k]
    return [(docs[i], scores[i]) for i in top_idx]

# ========== 4. Prompt 组装 ==========
def rag(query):
    hits = retrieve(query)
    context = "\n".join([f"- {d}" for d, _ in hits])
    prompt = f"基于以下资料回答问题：\n{context}\n\n问题：{query}\n回答："
    resp = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
    )
    return resp.choices[0].message.content, hits

# ========== 5. 测试 ==========
answer, refs = rag("我工作了 3 年，能休几天年假？")
print("📌 回答：", answer)
print("📎 引用：", refs)

"""
进阶版 RAG · 加入 Rerank + Query 改写 + 混合检索
"""
from langchain.retrievers import EnsembleRetriever, ContextualCompressionRetriever
from langchain.retrievers.document_compressors import CohereRerank
from langchain_community.retrievers import BM25Retriever
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_chroma import Chroma
from langchain_core.prompts import ChatPromptTemplate

# ========== 1. 向量检索 ==========
vectorstore = Chroma.from_documents(chunks, OpenAIEmbeddings())
vector_retriever = vectorstore.as_retriever(search_kwargs={"k": 10})

# ========== 2. BM25 关键词检索 ==========
bm25_retriever = BM25Retriever.from_documents(chunks)
bm25_retriever.k = 10

# ========== 3. 混合检索（RRF 加权融合） ==========
hybrid = EnsembleRetriever(
    retrievers=[vector_retriever, bm25_retriever],
    weights=[0.6, 0.4]   # 向量检索权重 0.6，BM25 权重 0.4
)

# ========== 4. 加 Rerank 精排 ==========
compressor = CohereRerank(model="rerank-multilingual-v3.0", top_n=4)
retriever = ContextualCompressionRetriever(
    base_compressor=compressor, base_retriever=hybrid
)

# ========== 5. Query 改写（可选） ==========
rewrite_prompt = ChatPromptTemplate.from_messages([
    ("system", "把用户问题改写成 3 个不同角度的检索查询，每行一个，不要编号。"),
    ("human", "{question}")
])
rewriter = rewrite_prompt | ChatOpenAI(model="gpt-4o-mini")

def multi_query_retrieve(question):
    queries = rewriter.invoke({"question": question}).content.split("\n")
    all_docs = []
    for q in queries:
        all_docs.extend(retriever.invoke(q))
    # 去重
    seen = set()
    return [d for d in all_docs if not (d.page_content in seen or seen.add(d.page_content))]

# ========== 6. 完整 RAG 链 ==========
template = """你是企业知识助手。请基于【参考资料】回答，每条结论标注引用编号 [1][2]。

【参考资料】
{context}

【问题】
{question}"""

docs = multi_query_retrieve("公司年假规定是什么？")
context = "\n\n".join([f"[{i+1}] {d.page_content}" for i, d in enumerate(docs)])

llm = ChatOpenAI(model="gpt-4o")
answer = llm.invoke(template.format(context=context, question="公司年假规定是什么？"))
print(answer.content)

评估体系 · 没有指标的 RAG 就是在裸奔

RAGAS 四件套 · 上线前必须跑通

🎯

Faithfulness 忠实度

答案的每句话是否都能在检索资料里找到依据？

目标：> 0.9
🎪

Answer Relevancy 答案相关性

回答是否切题？是否解决了用户的真实问题？

目标：> 0.85
🔬

Context Precision 上下文精确率

检索到的 TopK 中，真正相关的占多少？

目标：> 0.8
🔭

Context Recall 上下文召回率

回答问题所需的全部资料中，被检索到了多少？

目标：> 0.85

📈 优化方向 · 当指标不达标时，从哪里下手？

召回低

→ 优化 Embedding 模型 / 加 HyDE / 加 BM25 / 改写 Query

精确低

→ 加 Reranker / 缩小 TopK / 加元数据过滤

忠实低

→ 强化 Prompt 约束 / 减小 temperature / 引用强制

相关低

→ 改 Prompt / 微调 Embedding / 换更大模型

从 Demo 到生产，需要跨越的 6 道坎

01

文档切分不是越细越好

chunk_size 太小→语义断裂；太大→噪声多。一般 300-800 字 + 10-20% 重叠是甜蜜点。

02

混合检索是默认选项

纯向量检索会漏掉精确术语（型号/编号/人名），纯 BM25 会漏掉语义相关。生产环境 80% 用混合。

03

Rerank 几乎一定要加

实验数据：加 Reranker 后，Top1 命中率平均提升 30-50%，且能省下大模型 token。

04

引用必须做

金融/医疗/法律场景强需求。即使 ToC 场景，引用也能极大提升用户信任度。

05

建立 Bad Case 闭环

每周抽样 100 条 bad case，分析是检索错/改写错/生成错，对症下药。

06

冷启动先做"召回漏斗"

先跑离线评估调召回率，再上 Rerank 调精确率，最后调 Prompt 调忠实度。顺序不能反。
